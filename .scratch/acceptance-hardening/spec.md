# 航运智能账单助手 —— 验收与架构差距收尾（Spec）

## Problem Statement

笔试项目已实现全部 10 条验收标准、测试全绿（183 条），但架构方案里若干 harness 承诺尚未落到代码，交付物（Git 首次提交与 zip、OCR 端到端复验、文档与实际状态一致性）也未完成。评审若追问「harness 工程深度」或要求实际交付，当前状态仍存在可被指出的缺口。

## Solution

以最小、低风险、可离线测试的方式补齐「架构承诺 vs 实现」之间的差距，并完成交付收尾。已落地三项（OCR 瞬时错误重试、AR/AP 走 reasoner 强模型、每节点耗时追踪），剩余项按用户故事逐项实现并测试，所有新行为都必须离线可测、不引入真实外部调用。

## User Stories

1. As a 评审人, I want OCR 网关瞬时错误（5xx / 连接失败 / 超时）自动指数退避重试，而 4xx 客户端错误立即失败，so that 临时网络抖动不会把本可成功的单据错误转人工，也不会把次数浪费在不可能成功的请求上。
2. As a 财务复核人, I want AR/AP 语义佐证默认使用 deepseek-reasoner 强模型且可配置关闭，so that 佐证质量与架构的模型分层承诺一致。
3. As a 运维, I want 每个图节点记录进入/退出与耗时且 correlation_id 全程一致，so that 慢节点可以被定位，而不是只能看到整体启动日志。
4. As a 交付者, I want 仓库有首次提交并且可以打包成 zip，so that 满足「提供 Git 仓库链接或代码 zip」的交付要求。
5. As a 交付者, I want 用真实样例复验 OCR 端到端（对象存储桶存在 + OCR 网关能拉到 staged 文件），so that 交付前确认扫描件/图片路径真的能跑通，而不是只停留在配置就绪。
6. As a 交付者, I want README 与规格文档里的测试数、OCR 就绪状态、模型说明与代码一致，so that 评审不会发现文档自相矛盾。
7. As a 架构评审人, I want 主流程支持可选的状态持久化与断点续跑（默认关闭），so that 满足架构对持久化与审计回放的承诺，同时不改变单次 CLI 与离线测试的行为。
8. As a 架构评审人, I want OCR 结果按文件内容缓存且命中缓存不重复消耗 OCR 预算，so that 同一文件重复处理不会重复调用网关。
9. As a 架构评审人, I want 每节点可观测性在耗时之外补上输入/输出摘要与 token、OCR 用量，so that 满足架构的可观测性承诺。
10. As a 架构评审人, I want 扫描件 OCR 失败时先尝试降采样或裁剪的二次识别，so that 降级不只是「有文本层的 PDF 回退本地提取」一种。
11. As a 运营, I want 未命中费用名字典的费用给出建议标准名并可回填，so that 标准化字典随业务持续收敛，而不是未命中就永远原样返回。
12. As a 财务复核人, I want 冲突、低置信度、解析失败的审计轨迹保持可追溯，so that 本次加固不引入「静默通过」或「吞掉真实原因」的回归。
13. As a 交付者, I want 重试失败、缓存失败等新错误路径最终仍以 PENDING_REVIEW 或真实异常呈现并写明原因，so that 新路径不会伪装成「成功转人工」。
14. As a 评审人, I want 新配置项全部外置在配置层而非硬编码，so that 阈值与模型开关可维护、可审计。

## Implementation Decisions

- 用户故事 1、2、3、6 已在本会话实现并通过全量测试。
- OCR 重试只针对瞬时故障（5xx / 连接失败 / 超时），4xx 客户端错误立即上抛；重试上限与退避系数由配置层提供，不硬编码。
- AR/AP 佐证通过模型路由的 reasoner 开关切换强模型，默认开启，关闭即回落默认模型；确定性方向判定与「冲突转人工」逻辑保持不变。
- 节点追踪只记录节点名与耗时，不序列化 state：整段打进日志会再次引入凭据泄漏面，且高频节点日志会淹没可读性。
- 状态持久化做成可选开关，默认关闭；开启时在运行入口编译图时注入持久化后端。默认关闭保证离线测试与单次运行行为完全不变。
- OCR 缓存以文件内容哈希为键、带 TTL；命中缓存不扣 OCR 次数。缓存键必须覆盖完整文件内容，避免同名不同内容的文件互相污染。
- 降级链扩展为：OCR 失败 → PDF 文本层（已有）→ 扫描件降采样/裁剪二次识别 → 仍失败转人工。每级降级都写审计轨迹。
- 费用名建议是可选增强：未命中字典时默认仍原样返回（保持现状），建议标准名只在明确启用时产出，且必须离线可测。

## Testing Decisions

- 只测外部行为，不测实现细节；新增测试全部离线，沿用现有夹具统一替换 AR/AP 佐证与语义复核的模型调用，未 mock 的结构化提取离线失败。
- 优先复用现有 seam，不新增多余 seam：端到端走运行入口并 mock 结构化提取；OCR 在网关调用层注入；AR/AP 在模型路由层注入；配置就绪在配置/staging 判定层断言。
- 已新增的用例：OCR 瞬时错误重试后成功、4xx 不重试、AR/AP 佐证携带 reasoner 标志。
- 回归护栏：改动 OCR / AR/AP / 图组装后必须跑对应测试与全量测试；测试总数随新增用例同步更新到文档。

## Out of Scope

- 费用行分片并行提取与分片完整性对账（架构的 Sectioning 方案）：改动大、对考试收益边际，本次不做。
- 独立权限系统模块（auto/confirm/deny 三级强制层）：当前靠「UPDATE 字段级继承 + 只写新文件」隐式满足，显式模块化留待后续。
- 指标采集管线、云部署、鉴权、多租户、任务历史持久化（沿用既有前端与 API 规格的非目标）。
- 任何把真实客户单据上传到公网服务的做法。
